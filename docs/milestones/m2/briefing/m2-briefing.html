唯一条件：GitHub Actions 账户计费／runner 外部阻断仍未解除，因此 AC-01、VM-01 保持 BLOCKED-EXTERNAL。本地全绿证据不冒充远端单次 CI 全绿。

执行摘要

M2 已完成六要素冻结、总体方案与详细计划、五轮实现迭代和三轮独立验收。R3 在原生 Windows、临时 venv、新 detached worktree 以及隔离 HOME／状态目录中复跑后，确认产品能力、交付物符合度、代码评审和真实测试四个维度均通过；唯一未闭合项是仓库账户侧的 GitHub Actions 计费／runner 外阻。

出口门禁原文：“dshd 能可靠管理并连接真实 Harness；相关 runner 场景可执行”。

本里程碑的“可靠管理”包含单写、持久 desired、generation、崩溃恢复与有界关闭；“连接”包含 exact authority、cookie exchange 和真实 probe；“可执行”要求 runner 的 driver 真正运行并断言，而不是仅在清单中声明。R3 两轮真实链与 runner 的诚实计数已经重现这些事实。结论因此是“有条件通过”，不是把外部阻断改写为 PASS，也不是将 66 个 declared 向量全部宣称为已执行。

实现与迭代史

迭代 1：主体能力落地｜7e031eb

在 M1 骨架上首次真实化 config、identity、state、supervisor、harness 与验收工具。这里必须与 M1 遗留提交 faeab2f 区分：M2 相关实现以 7e031eb 起算。R1 独立验收结论为未通过独立验收，形成 F01～F07：真实入口不可重复构建、delete-rename 窗口、哨兵锁、CI 口径、直杀式停止、reducer/snapshot 覆盖不足，以及错误的环境归因。

迭代 2：真实链准备与 fixture 稳定｜224921981

冻结 lock 安装与真实 Harness 诊断链被跑通，fake/stub 对 Windows 瞬时 I/O、部分响应和 16 KiB 上限补强。但当时 dshd main 尚未装配 supervisor/effect executor，所以诊断 driver 不得冒充产品自动恢复；这一诚实边界写入 iteration-r2-fixes。

迭代 3：产品装配闭环｜1270feb4

main 按 config→identity→desired→guard→coordinator→supervisor 装配，effect executor 通过反馈通道驱动 Spawn、Bootstrap、Backoff、Stop；修复 stdin 竞争、ready 分片、header 大小写和真实 settings probe。产品链开始真实到达 generation 1→2 与 STOPPED。

迭代 4：R1 七项发现结构化修复｜2f03dbe / 2f3a05f

不可重复构建改为 frozen install/build，并增加 dsh/apps/cli/lib/bin.js digest 门；delete-rename 改为平台原子替换；create_new 哨兵文件改为 fs4 持有的 OS 内核锁；AC-01/VM-01 改为 BLOCKED-EXTERNAL；停止从直接 kill 演进为 graceful→8s→force 树停止；reducer 优先级与 immutable snapshot 补齐。R2 随后仍因 F08 文档断链、F09 shutdown 卡在 STOPPING 而未通过。

迭代 5：停止竞态与证据闭环｜cadb8e0 / 8e1c501

Stop effect 移至独立线程，child monitor 与 stop worker 可并发；typed stop、hold deadline、OS termination 统一为 Event::Shutdown；补 child-gone-before-stop-event、stop-event-before-child-gone 和 duplicate-shutdown 双序确定性测试。调用方以 v1.1 修复 13 个断链，并在原生 Windows Python 3.12 venv 验证 10 paths、42 schemas、174 links、66 declared、0 executed，纠正 R1 的 Cygwin wheel 归因。

第三轮独立验收｜ceb64b5

R3 重跑两轮干净产品链、三轮 ignore-termination、CF-01、runner 和原生 validator，确认 F01～F09 均已闭合且无新增 F10。最终结论为有条件通过；唯一条件仍是外部 GitHub Actions 计费／runner 阻断。

两轮干净产品链

PID 14204→17244 与 18456→6548。两代均 exchange=303、probe=HTTP_200；第一代 crash 后 1000ms backoff；停止执行 graceful→8s→force，最终 STOPPED。两轮使用相同 bin.js SHA-256 dc23f6…3166。

停止竞态压力

3 × max sequence=7

三轮 hold/ignore-termination 均观察 READY→STOPPING→STOPPED、child_gone=true、daemon_exited=true；外层预算包含 15 秒 hold、8 秒 graceful 窗及退出余量，没有用评审强杀冒充有效样本。

CF-01 双进程

owner 15016 / competitor 16800

owner 持 LockFileEx 对应 OS 锁、child 14824 达 READY；competitor 在 10 秒内退出，仅报告 WRITER_GUARD_HELD，无 Spawn/Ready；owner 关闭后树和 daemon 均消失。

契约与 runner

66 declared / 4 executed

原生 venv validator：10 paths、42 schemas、179 local refs、174 links、66 declared、0 executed。runner：declared=66 executed=4 passed=4 failed=0。reference-stub 自检包含 route_probe=13/13。

这些数字分别回答“契约声明多少”“本地 driver 实际执行多少”“真实产品链是否可重复”三个问题，不能互相替换。尤其是 executed=4 不代表只存在四个向量，declared=66 也不代表 66 个行为均已通过。

代码评审PASSreducer 是状态单事实源；typed Event/Effect 串行归约；immutable snapshot 不允许消费者反写；core 与 OS/网络 adapter 分层清晰。

持久化与锁：AtomicFile 使用同目录原子提交，不再存在 delete-then-rename 缺文件窗口；WriterGuard 持有 fs4 File handle，Windows 映射 LockFileEx、Unix 映射 flock，锁文件存在本身不代表锁被占用。

认证与秘密：ReadyUrl 只接受 loopback exact authority，真实 probe 成功后才发布 connection context；Secret 的 Debug 固定脱敏，launch token 和 cookie 不写入持久模型或报告。

进程树所有权：按源码事实表述，Windows 当前使用 CREATE_NEW_PROCESS_GROUP、taskkill /T、8 秒后 /F，再以精确 Child handle kill/wait；Unix 使用独立 process group 与负 PGID TERM/KILL。当前实现没有虚构为 Windows job object。

遗留事项与下一步

  1. 关闭唯一验收条件。由账户所有者解除 GitHub Actions 计费／runner 外阻，在与 R3 对应的同一代码状态取得一次 build、lint、typecheck、unit、contract、real-harness、runner、secret 全绿 run 与 artifact。完成后将 AC-01、VM-01 从 BLOCKED-EXTERNAL 转正；预案已备，不用重写本地真实测试事实。
  2. 后续维护强化。Windows job object 可作为更强的 descendant containment 方案；Node DEP0190 对应的 shell: true 参数调用可改成无 shell 的安全 argv。两者是维护项，不是本轮验收失败。
  3. 进入 M3。管理面 start/stop/restart 与 operation/idempotency 应复用 M2 的 typed lifecycle port、immutable snapshot 和 connection context；不得绕过 coordinator 直接修改 observed state，也不得将四个 executed 场景扩写成 66 个行为已通过。
范围边界继续有效：中央注册／心跳／lease 属 M6；管理 API 属 M3；HTTP/WS 透明代理属 M4/M5；跨 task single-attach 属部署层。M2 通过不证明这些后续能力已经交付。
