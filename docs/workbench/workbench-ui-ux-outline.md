# Kunora Workbench UI/UX 文字大纲

2026-08-30 修订补充：以 [静态稿索引](ui-mockups/README.md) 和 [修订交互规范](ui-mockups/revision-2026-08-30/interaction-spec.md) 为当前设计基线。任务名称、介绍可选；消息采用连续对话与内联执行过程，而非仅日志流。作业和节点不在消息输入区切换；仓库页仅浏览任务绑定分支。基本信息增加完整度、编辑失败和里程碑详情；成果拆分生成与验收状态并按不可变版本验收。以下十二页范围已扩展为十五个静态状态，交互测试仍待进行。

## 1. 设计目标

工作台采用典型桌面工作台布局：左侧任务列表导航栏持续提供任务关联、过滤和选择；右侧作为任务工作区，根据是否选中任务展示使用指南或任务工作面板。[BIZ-05]

本阶段只定义信息架构、页面职责、状态和关键交互。视觉风格、组件规格、响应式规则、静态稿和交互稿在本大纲确认后继续设计；任务分支内的目录结构与结构化文件格式另行定义。[BIZ-02]

## 2. 核心对象

| 对象 | UI 中的含义 |
| --- | --- |
| 任务 | 一个 Git 代码仓库中的一个分支，是工作台管理和执行的基本对象。 |
| 任务基础信息 | 独立于六要素的任务描述，至少包括任务名称和任务介绍。 |
| 任务定义 | 任务基础信息、任务级六要素、总体方案和路线图的集合。 |
| 六要素 | 最终目标、整体工作方法、边界、约束、交付物、验收；验收下分验收标准和验收方法。 |
| 路线图 | 由有顺序的里程碑组成，用于表达任务的推进路径。 |
| 里程碑 | 路线图中的阶段对象，最终需要自己的六要素、总体方案和详细计划。 |
| 执行 | 任务通过中央服务分配给后端节点，并由 `dshd + dsh` 实际完成的过程。 |

## 3. 自动初始化

任务关联成功即表示任务已经创建。工作台随即自动向中央服务提交初始化请求，由中央服务分配后端节点并调用对应 `dshd` 完成任务初始化；产品中不再存在“启动任务”按钮、启动确认或定义完整度门禁。[BIZ-04]

| 规则 | UI 表现 |
| --- | --- |
| 关联后自动初始化 | 任务立即进入列表，并显示初始化进度，无需用户再次确认。 |
| 定义与初始化解耦 | 名称、介绍、六要素、总体方案、路线图或里程碑内容不完整时仍正常初始化；界面只提示完善程度。 |
| 初始化成功 | 状态变为“已初始化”，任务工作区建立与 dsh 的交互能力。 |
| 初始化失败 | 保留任务关联和已填写内容，显示失败原因及“重试初始化”入口。 |
| 初始化范围 | dshd 具体执行哪些初始化动作及完成判定，由后续任务初始化契约定义，本轮不提前规定。 |

## 4. 整体布局

工作台是一个占满可用页面空间的左右双栏界面，不使用居中的独立卡片承载整个应用。[BIZ-05]

```text
┌──────────────────────┬──────────────────────────────────────────────────┐
│ 关联任务             │ 未选择任务：六格简笔画使用指南                 │
│ 快速过滤             │                                                  │
│                      ├──────────────────────────────────────────────────┤
│ 可滚动任务列表       │ 已选择任务：固定任务标题栏                     │
│                      │ 基本信息｜消息｜仓库｜作业｜成果｜团队｜工作流 │
│                      │ 当前选项卡内容                                   │
└──────────────────────┴──────────────────────────────────────────────────┘
```

- 左侧任务列表导航栏与右侧任务工作区始终同时存在。
- 左侧任务列表区域独立上下滚动，顶部“关联任务”和快速过滤输入框保持可见。
- 右侧未选择任务时显示使用指南；选择任务后切换为该任务的工作面板。
- 任务工作面板的标题栏固定在顶部，MVP 只显示当前任务标题。[BIZ-05]

## 5. 左侧任务列表导航栏

左侧导航栏从上到下固定为三部分：[BIZ-05]

1. **关联任务按钮**：位于最上方，是导航栏的主要操作；提交仓库分支后创建任务并自动触发初始化。[BIZ-04][BIZ-05]
2. **快速过滤输入框**：只过滤当前任务列表，帮助用户按任务名称或后续确定的任务检索字段快速定位。
3. **任务列表**：占用导航栏剩余高度并独立上下滚动；点击任务后在右侧打开工作面板，左栏位置不变。

任务名称尚未填写时，不自动编造名称；任务项使用仓库和分支保持可识别，并明确提示基础信息待完善。[BIZ-02][BIZ-03]

## 6. 右侧未选择任务状态

未选择任务时，右侧展示一幅六格简笔画形式的工作台使用指南，不显示空白任务面板。[BIZ-05]

六格内容围绕完整主路径组织：

1. 关联 Git 仓库分支。
2. 系统创建任务并自动初始化。
3. 完善任务基本信息与六要素。
4. 编写总体方案和路线图。
5. 查看消息、仓库和 dsh 作业。
6. 汇总成果，并按需使用团队与工作流。

每格由一幅简笔画、一句短标题和一句简短说明组成；具体画风与文案在静态稿阶段确定。

## 7. 右侧任务工作面板

### 7.1 固定标题栏

- 选择任务后，右侧顶部显示固定标题栏。
- MVP 标题栏只放置任务标题，不增加状态、按钮、面包屑或指标。[BIZ-05]
- 当任务名称尚未填写时，标题显示明确的未命名状态；仓库和分支不冒充任务名称。[BIZ-03]

### 7.2 选项卡导航栏

标题栏下方显示任务选项卡，顺序固定如下：[BIZ-05]

| 选项卡 | 内容 | MVP 属性 |
| --- | --- | --- |
| 基本信息 | 显示和编辑任务结构化信息、六要素、路线图和总体方案；路线图中的里程碑从这里进入。内容区必须提供明确的编辑入口。 | 必选 |
| 消息 | 按时间顺序显示任务实时执行日志。 | 必选 |
| 仓库 | 显示关联 Git 仓库分支的文件和目录列表，支持进入目录并查看文件。 | 必选 |
| 作业 | 显示当前 Kunora 任务下由 dsh 执行的作业信息，以 `JOB-...` 标识；不得使用“任务”称呼 dsh 作业。 | 必选 |
| 成果 | 显示任务已经形成的交付成果。 | 必选 |
| 团队 | 显示使用该任务的团队；一个任务可能对应多个团队。 | 可选 |
| 工作流 | 显示该任务使用的工作流。 | 可选 |

当前静态稿保留“团队”和“工作流”页签，并以“功能建设中”页面如实表达尚未开放；进入产品实现阶段后，再根据能力开关决定是否显示。[BIZ-05][BIZ-06]

### 7.3 选项卡内容区

- 内容区只显示当前选项卡内容，不同时铺开多个模块。
- 切换选项卡不改变当前选中的任务。
- 切换左侧任务后，右侧标题和选项卡内容整体切换到新任务。
- 长内容在右侧内容区内部滚动，固定标题栏保持可见。

## 8. 主要交互

### 8.1 关联和选择任务

1. 用户点击左栏顶部“关联任务”。
2. 用户关联 Git 仓库分支，任务立即加入左侧列表并自动初始化。[BIZ-04]
3. 用户点击任务项，右侧从六格指南切换到该任务工作面板。
4. 工作面板默认打开“基本信息”选项卡。

### 8.2 快速过滤任务

1. 用户在快速过滤输入框输入内容。
2. 左侧任务列表即时缩小到匹配项。
3. 过滤操作不改变右侧已经选中的任务；用户选择新的匹配项后才切换右侧内容。

### 8.3 浏览任务内容

1. 用户通过选项卡切换任务视图。
2. 在“仓库”中逐级进入目录并打开文件。
3. 在“消息”中持续查看实时执行日志。
4. 在“基本信息”中查看或编辑任务定义，并进入路线图里程碑。

### 8.4 关联与初始化异常恢复

1. 关联表单校验失败时保留用户输入，并在对应字段附近显示原因与恢复动作。
2. 仓库分支已经关联时，不重复创建任务；显示已有任务名称并提供“打开已有任务”。
3. 初始化失败时保留任务关联和已填写内容，不显示任务页签。
4. 初始化失败页显示失败步骤、失败原因和“重试初始化”；重试后重新进入初始化进行态。

## 9. 静态稿范围

文字大纲确认后，静态稿覆盖以下十二个桌面画面：

1. 未选择任务时的双栏工作台与六格使用指南。
2. 关联任务弹窗。
3. 关联任务重复校验失败状态。
4. 任务自动初始化进行状态；不显示选项卡导航。
5. 任务初始化失败与重试状态；不显示选项卡导航。
6. 选择任务后的“基本信息”选项卡。
7. “消息”选项卡的连续会话状态。
8. “仓库”选项卡的文件与目录浏览状态。
9. “作业”选项卡的 dsh 作业信息状态。
10. “成果”选项卡的任务交付成果状态。
11. “团队”功能建设中状态。
12. “工作流”功能建设中状态。

“团队”和“工作流”作为可选模块，不阻塞 MVP 主静态稿评审。[BIZ-05][BIZ-06]

## 10. 后续单独定义

- 左栏宽度、断点、字体、颜色、间距和组件视觉规范。
- 六格简笔画的具体画面、文案与视觉风格。
- 各选项卡的字段、空状态、错误状态和操作权限。
- Git 文件预览范围及不支持的文件类型处理方式。
- 团队与工作流选项卡的启用条件和数据结构。
- dshd 的任务初始化动作、初始化契约和完成判定。
