# Kunora Workbench 静态稿统一设计契约

版本：v1.1

日期：2026-08-30

状态：修订设计基线，交互待验证

v1.1 在保留 v1.0 术语、任务身份、布局和示例日期的基础上修订。新增 [交互规范](revision-2026-08-30/interaction-spec.md) 是本契约的组成部分。2026-08-29 为虚构示例时间，不代表当前真实任务状态。

本契约是 Kunora Workbench 静态稿的统一输入。后续页面不得各自编造术语、对象 ID、时间线、任务状态或页面能力。

## 1. 根因分析

| 问题 | 表层现象 | 根本原因 |
| --- | --- | --- |
| 任务/作业混用 | 基本信息页仍显示“任务”，其他页显示“作业” | 页签更名发生在部分页面完成后；产品文档仍保存旧名称，缺少全局术语表。 |
| 六要素定义错误 | 基本信息页显示“目标、角色、场景、约束、输入、交付” | 单页生成时根据常见产品画布补全了内容，没有使用 Kunora 已确认的六要素定义。 |
| 基本信息不可编辑 | 页面只有只读信息 | 静态稿只表达信息结构，没有用“能力—入口”检查确认每项产品能力都有可见操作入口。 |
| 示例时间漂移 | 基本信息页使用 2024，其他页面使用 2026 | 每张图独立生成，没有共享示例数据集。 |
| 来源作业使用 TASK ID | 成果页的“来源作业”显示 `TASK-...` | 缺少对象类型与 ID 前缀约束，任务和作业在自然语言中又容易混淆。 |
| 初始化进度含义不清 | “第 4/6 步”与“58%”同时出现 | 没有定义步骤进度与数值进度的唯一语义。 |
| 缺少失败/重试 | 只画了关联和初始化成功主路径 | 原静态稿范围按页面模块列举，没有按任务生命周期列举必要状态。 |

这些问题来自同一类源头：静态稿是分轮生成的独立位图，缺少可复用的术语、对象、状态和示例数据契约。只改图片文字会再次产生漂移，因此必须先统一输入，再修订页面。

## 2. 统一术语

| 概念 | UI 固定名称 | 禁用名称/说明 |
| --- | --- | --- |
| Kunora 管理对象 | 任务 | 一个 Git 仓库分支。 |
| dsh 执行单元 | 作业 | 页签及所有执行记录统一使用“作业”，不再使用“任务”表示 dsh 作业。 |
| 任务产出 | 成果 | 成果可以追溯到来源作业。 |

任务工作面板页签顺序固定为：

`基本信息｜消息｜仓库｜作业｜成果｜团队｜工作流`

初始化进行中或初始化失败时，不显示任何工作面板页签。

## 3. 六要素固定定义

基本信息页必须使用以下六要素，不得替换为通用产品画布：

1. 最终目标
2. 整体工作方法
3. 边界
4. 约束
5. 交付物
6. 验收（包含验收标准与验收方法）

## 4. 对象与 ID 类型

| 对象 | ID 示例 | 可引用位置 |
| --- | --- | --- |
| 任务 | `TASK-20260829-0007` | 任务编号、关联任务、执行链路中的任务。 |
| 作业 | `JOB-20260829-0012` | 作业 ID、初始化作业、成果来源作业。 |
| dsh 会话 | `sess-20260829-104107-9f3b` | 作业详情、消息上下文、执行链路。 |
| 节点 | `dshd-node-03` | 执行节点、连接状态、执行链路。 |

字段名决定 ID 类型：“来源作业”只能引用 `JOB-...`；若需引用所属任务，必须单独显示“所属任务”并使用 `TASK-...`。

## 6. 页面能力与可见入口

| 页面 | 必须表达的能力 | 静态稿可见入口或状态 |
| --- | --- | --- |
| 基本信息 | 查看和编辑任务基础信息、六要素、总体方案、路线图 | 内容区显示“编辑任务定义”；不得把操作放入 MVP 固定标题栏。 |
| 消息 | 与 dsh 连续对话并查看执行过程 | 输入框、发送、当前作业、节点与连接状态。 |
| 仓库 | 浏览分支文件与目录并查看文件 | 目录树、文件列表、预览区。 |
| 作业 | 查看 dsh 作业及执行链路 | 列表、步骤、详情与链路。 |
| 成果 | 查看、追溯和验收成果 | 来源作业、仓库路径、验收状态与验收操作。 |

## 7. 初始化进度规则

初始化静态稿采用步骤进度，不展示容易产生第二含义的百分比：

- 顶部显示“正在执行第 4/6 步”。
- 进度条只作为整体位置提示，不标注百分数。
- 左侧任务项显示“初始化中 · 第 4/6 步”。
- 已完成步骤、当前步骤和未开始步骤必须同时通过图标、文字与颜色区分。

## 8. 生命周期状态矩阵

| 状态 | 是否显示任务页签 | 核心反馈 | 主操作 |
| --- | --- | --- | --- |
| 未选择任务 | 否 | 六格使用指南 | 关联任务 |
| 关联表单 | 否 | 仓库、分支、名称、介绍 | 关联并初始化 |
| 关联校验失败 | 否 | 字段级错误、保留输入 | 修正后重试；重复关联时打开已有任务 |
| 初始化中 | 否 | 当前步骤、节点、初始化作业 | 可离开页面，后台继续 |
| 初始化失败 | 否 | 失败步骤、原因、已保留内容 | 重试初始化 |
| 初始化完成 | 是 | 默认进入基本信息 | 编辑定义或切换页签 |

代表性错误静态稿至少覆盖：

1. 仓库分支已被关联：明确指出已有任务，并提供“打开已有任务”。
2. 初始化失败：保留任务和已填内容，显示失败步骤、错误原因及“重试初始化”。

仓库不可访问、分支不存在等同类错误在交互稿中沿用相同字段级错误组件。

| 原问题 | 预防控制 | 修复后的验收方式 | 是否形成闭环 |

| 任务/作业混用 | 第 2 节唯一术语与固定页签序列 | 检查所有已初始化页面页签均为“作业” | 是 |
| 六要素错误 | 第 3 节固定定义 | 基本信息页逐项核对六个名称 | 是 |
| 缺少编辑入口 | 第 6 节能力—入口映射 | 基本信息页可见“编辑任务定义” | 是 |
| 时间漂移 | 第 5 节共享数据集 | 基本信息页与其他页面统一到 2026-08-29 时间线 | 是 |

上述控制同时覆盖问题的当前修复和后续页面扩展；方案通过后再修改产品文档与静态稿。

## 10. v1.1 定向修订（优先于旧稿表现）

- 名称及介绍可选，只有仓库与分支必填；完整度不构成创建、初始化或消息交互门禁。
- 授权失败提供管理员修复指引、检查仓库访问权限及检查通过后的重试；恢复流程复用原任务并核对既有进度。
- 消息页的作业与节点为只读上下文；仓库页绑定仓库和分支只读，刷新文件列表不表示 Git 同步操作。
- 六要素使用可展开摘要，验收标准和方法独立呈现；基本信息展示四组资料完整度，里程碑内部三组资料另行统计。
- 无可计算总量的作业不显示百分比；允许请求停止，但不能声称撤销已经完成的操作。
- 成果生成状态与验收状态分开；只有已生成且可定位不可变版本的成果可验收。新版不继承旧版通过结论。
- 本轮补充编辑保存失败、里程碑详情、版本验收表单三张静态状态；并发冲突、断线、键盘与窄窗口规则见交互规范。
- 新版基本信息刻意展示验收信息尚待完善，替代旧图完整摘要；其它身份与示例时间保持原数据集。成果沿用同一虚构作业和版本标识。
- 新增按钮代表待实现的 UX 需求。仓库访问检查、保存版本校验、版本化验收等接口在实现前必须对齐后端，不能据此宣称接口已经可用。
