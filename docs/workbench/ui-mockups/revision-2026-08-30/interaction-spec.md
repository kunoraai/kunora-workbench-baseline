# UI/UX 修订交互规范

日期：2026-08-30。状态：修订设计，待交互原型验证；不是已实现能力清单。

本轮保留原有品牌、双栏布局、标题栏和七页签，修正评审发现的规则冲突。旧图不删除。本规范补充静态设计契约；如原图与本规范存在差异，以文字规则为实现依据并登记视觉差异，不把位图当作精确组件规格。

## 1. 关联与任务身份

- 仅仓库地址、已存在且可访问的分支是关联必填项。任务名称和介绍均可留空；定义完整度不能阻止创建、初始化或消息交互。
- 名称为空时标题显示“未命名任务”；左栏另外显示仓库与分支，并提示“基础信息待完善”，不得编造名称。
- 修改仓库地址后，清除之前的访问验证结果和分支选择；提交时重新校验仓库、分支和重复关联。
- 重复关联保留全部输入。“打开已有任务”切换到服务器返回的已有任务。“更换分支”聚焦分支选择，选择后清除重复错误并恢复“关联并初始化”。
- 校验和提交期间防止重复提交；提交结果不确定时先查询关联结果，不盲目再次创建。使用稳定请求标识的具体接口由实现阶段核对。
- 仓库页只浏览当前任务绑定分支，不提供改绑、checkout、pull 或 push。刷新仅重新读取文件列表和版本信息。节点由中央服务分配，消息页不提供节点切换。

## 2. 初始化及授权恢复

- 初始化中、失败和重试检查阶段均不显示工作页签。任务与填写内容持续保留。
- 六步只是本轮展示模型；实际步骤、完成判定必须映射后端初始化契约，不得用定时器制造成功或进度。
- 展示当前步骤、最后更新时间；连接中断显示“连接中断，当前进度可能已过期”，不得保留绿色实时标记。
- 授权错误：提示仓库管理员恢复执行节点的仓库访问权限；提供“复制错误信息”和“检查仓库访问权限”。不在聊天、日志或表单中显示凭据。检查接口尚需与后端对齐，不宣称已经存在。
- 检查结果状态为检查中、仍不可访问、访问已恢复、检查失败。只有恢复后才启用重试；网络检查失败与授权失败分开显示。
- 重试前对账既有步骤和任务记录，复用现有任务，防止重复创建和重复执行有副作用的动作；不能预先承诺所有步骤都可断点续跑。
- 长时间无进展提示“等待后端更新”，可检查连接或查看错误详情；阈值随后端心跳契约确定，不凭空判定任务失败。

## 3. 定义编辑与里程碑

- 完整度分为四组：基础信息、六要素、总体方案、路线图。基础信息需名称及介绍；六要素需六项非空且验收标准、方法分别非空；方案需正文；路线图需至少一个含名称和计划时间的里程碑。只表示资料齐备，不判断内容质量。
- 当前图演示“3/4 项已完善，六要素待完善”；里程碑内部完整度单独显示，不能与任务四项混算。
- 六要素摘要允许展开全文。验收标准、验收方法独立编辑。编辑区导航覆盖基础信息、六要素、总体方案、路线图。
- 保存期间禁用重复保存。成功后更新内容和版本；失败保留输入，显示“保存失败，修改尚未写入”，提供重试。没有服务端成功确认，不显示“已保存”。
- 并发版本冲突显示“内容已更新，请先比较版本”；保留本地草稿，允许查看差异、复制草稿、重新载入，不静默覆盖他人修改。
- 未保存时关闭、切换任务或离开编辑区：提供“继续编辑”和“放弃修改并离开”；不得直接丢失草稿。草稿保留范围为当前会话，不承诺跨设备持久化。
- “查看里程碑”进入当前任务的里程碑详情，显示自己的六要素、总体方案、详细计划和资料完整度；明确“返回任务基本信息”。里程碑编辑沿用保存和冲突规则。

## 4. 消息与作业

- 消息发送目标固定为当前任务；显示当前作业 ID 和自动分配节点，详情入口只打开当前作业。
- 每个任务独立保留当前会话内未发送草稿；切换任务时不得把草稿、上传附件或发送目标串到其他任务。
- 发送中、已发送、发送失败、结果待确认分别表达。失败保留消息；确认未送达后才重发；不确定时先核对消息记录，避免重复执行。
- 执行中提供“停止执行”；操作进入“正在请求停止”，只有后端确认才显示“已停止”。说明停止不撤销已完成的文件或外部操作。
- 长工具输出默认折叠，允许展开与复制；用户上翻时不强制滚到底部，新增消息提供提示。
- 断线时保留历史并标记更新时间，暂停发送并允许编辑草稿；重连需重新确认任务上下文，再恢复发送。
- 作业没有可解释总量时只显示“执行中”、当前步骤及已用时，不显示估算百分比。若有总量，提供完成数/总数及口径。
- 路线图进度必须明确数据来源；静态示例数字不是运行时计算规则。

## 5. 成果和版本验收

- 生成状态：草稿、生成中、已生成、生成失败。验收状态：不可验收、待验收、已通过、需修改。
- 只有已生成、可读取且具有不可变版本定位的成果可开始验收。草稿和生成中必须显示不可验收，不使用“待验收”混淆。
- 图中短提交号仅供展示；实现使用仓库身份、完整 commit SHA、路径及文件摘要定位成果。验收记录包含版本、结论、评语、验收人和服务器时间。
- 开始验收打开表单，显示成果名称、来源作业、路径、版本，提供完整预览。结论必须显式选择“通过”或“需修改”；需修改时评语必填。
- 未选择结论时提交禁用。提交失败保留填写内容；成功后显示验收记录。无权限时只读并说明原因。
- 提交前重新核对版本与权限；版本已变化时保留评语、提示重新查看新版本，不能把旧评语直接记为新版本已通过。
- 新版本进入待验收，旧版本记录仍保留。“通过”不等于 Git merge、push 或生产发布，不自动触发这些操作。
- 完整预览按所选版本读取；读取失败、文件不存在、格式不支持要明确反馈，不能展示无关旧缩略图。

## 6. 布局与可访问性交互要求

- 保留桌面双栏：左侧列表、右侧任务区各自滚动。标题栏只显示标题，操作均在内容区。
- 实现候选规则：1440 宽保持现有密度；1024–1279 将仓库目录树收起到可展开面板，预览改为列表/预览切换；更窄窗口允许任务导航折叠，保留明显返回入口。断点需在原型中实际验证。
- 文本可换行；路径/ID 可复制并查看完整值，不依赖悬停。表格优先减少次要列，必要时局部横向滚动，不能让整页横向溢出。
- 全部控件支持键盘和可见焦点；弹窗进入后焦点位于标题或首个输入，Tab 不逸出，Esc 按未保存规则关闭，关闭后焦点返回触发入口。
- Tabs、表格、输入、错误和状态需有语义及可访问名称；错误关联字段，动态状态适度播报，不逐 token 打断读屏。
- 状态必须有文字，不只依赖红绿颜色。检查字体缩放、200% 放大、减少动态效果偏好，以及图标按钮的可见标签或可访问名称。
- 对比度、目标大小、键盘行为、读屏和响应式均待代码原型测量，本次位图不构成通过证明。

## 7. 最小验证场景

| 场景 | 预期 |
| --- | --- |
| 空名称关联 | 成功创建且自动初始化，明确未命名状态 |
| 重复分支后更换 | 保留其他字段，可以关联新分支 |
| 授权失败后恢复 | 管理员修复、检查通过、重试原任务，无重复任务 |
| 保存失败或并发冲突 | 输入保留，不假报成功，不覆盖远程新版本 |
| 切换任务后发送 | 草稿和发送目标均属于当前任务 |
| 消息发送结果不确定 | 先核对，不重复触发执行 |
| 停止执行 | 等待后端确认，解释已完成操作不可撤销 |
| 生成中成果 | 禁止验收 |
| 验收时版本变化 | 阻止把旧版结论应用到新版 |
| 窄窗口、放大、纯键盘 | 主操作可达、内容不丢失、焦点可见 |
